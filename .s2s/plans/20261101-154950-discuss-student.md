## Overview

Everything a student sees in Moodle. On the quiz attempt review page and the assignment view
(feedback) page, the plugin injects a container; an AMD module asks a plugin AJAX endpoint for the
advisory state, which the endpoint obtains from Vektra `GET /api/v1/assess/state` on every request
(no cache of any kind). The button and the pre-session screen are rendered from that response with
Mustache. On "Inizia", the endpoint mints a pre-session token server-side (assess:mint key,
positive login-as assertion, plugin version) and the AMD module hands it to the Vektra-origin
iframe through an origin-checked postMessage. Students download their own transcripts through a
streaming proxy that uses a single-use download token. Moodle 4.3 needs the legacy
`before_footer` callback; 4.4+ uses `\core\hook\output\before_footer_html_generation`.

This is the first Mustache and first AMD code in the vektra-moodle family.

## Design Notes

**Hook matrix**:

| Moodle | Mechanism | File |
|---|---|---|
| 4.3 (403) | legacy callback `local_vektradiscuss_before_footer()` | `lib.php` |
| 4.4+ incl. 5.2 | `\core\hook\output\before_footer_html_generation` callback `\local_vektradiscuss\local\hook_callbacks::before_footer` | `db/hooks.php` |

Both delegate to one renderer entry `\local_vektradiscuss\local\injector::inject(): string`. On 4.4+
core skips the legacy callback when a hook callback is registered for a hook implementing
`deprecated_callback_replacement`; task A1 verifies this on 5.2 (no double render, no deprecation
debugging) and that the `db/hooks.php` entry is inert on 4.3.

**Target pages** (by `$PAGE->pagetype` and `$PAGE->cm->modname`, nothing else):
`mod-quiz-review` (attempt review: pass the viewed attempt id for the state 9 pointer only),
`mod-quiz-view` (summary of attempts), `mod-assign-view` (feedback). Any other page: return ''
without any HTTP call. The injector also returns '' when the site kill switch is off, the cm is not
quiz/assign, or the user lacks `local/vektradiscuss:start` and `:viewowntranscript`.

**Why AJAX and not server-side render in the hook**: the hook must never block a results page on
Vektra latency or outage. The hook only emits a placeholder (`<div data-region="local_vektradiscuss"
data-cmid=...>`) and `js_call_amd`. The state call happens in `ajax.php`.

**Endpoint** (`ajax.php`, AJAX_SCRIPT, block_vektra skeleton) with `action` in {`state`, `mint`}:
1. `require_login($course, false, $cm)`; `require_sesskey()`; `require_capability('local/vektradiscuss:start', context_module)`
   (`state` also accepts `:viewowntranscript` so students who lost start rights still see links).
2. Login-as check: `\core\session\manager::is_loggedinas()` or `!empty($USER->realuser)` ->
   respond with the local state `loginas` (REQ-068 state 8 text), make **no** Vektra call, emit
   no token. This is the fast path; the positive assertion below is the authoritative one.
3. Mint (`POST /api/v1/assess/tokens`, key role `mint`): body carries `sub` = `$USER->id`,
   `cmid`, `courseid`, `loginas: false`, `realuser_id: null`, `plugin_version`. Fields are always
   sent explicitly (positive assertion; Vektra refuses absence, ARCH-067). Moodle ids are hints,
   re-resolved by Vektra (REQ-095).
4. `state`: mint, then `GET /api/v1/assess/state?cmid=` with the token as bearer; return the state
   DTO only (never the token). `mint`: mint, return `{token, ui_origin, expires_in}`.
5. Any non-2xx, transport error or unknown state value -> `{state: "unavailable"}` (REQ-068 state
   7, generic text). No error code, message or request id reaches the browser; the request id goes
   to `debugging()` only.

Integration risk: INT-001 defines `/state` as token-authenticated, so every page view mints a token
that is never used for Start. If plan 8 adds a key-authenticated `/state` (assess:mint key + sub),
step 4 drops the mint; otherwise the unused-mint volume must be accepted by the mint-to-Start audit
correlation (ARCH-067). Raise with 20261101-154950-assess-session-lifecycle.

**No caching**: no `$SESSION`, no MUC, no `cache::make`, no static, no `localStorage`/
`sessionStorage` in AMD. block_vektra caches its widget token in `$SESSION`; that pattern must not
be copied (COMP-001). Enforced by a grep guard in CI (task F3).

**States rendered** (REQ-068 1-11 plus local `loginas`): the DTO carries `state`, `reason`,
optional `date` (only when Vektra sends it: Vektra decides whether a date may be shown), `minutes_left`,
`session_number`, `selected_attempt` (number), `transcripts[]` (`tid`, `n`, `available`,
`purged`), `pre_session` block (duration, recipients by role and name, RAG used flag, limits,
privacy summary + notice URL + version, previous sessions line, D2 file predictions when present).
The plugin renders strings from its own lang packs keyed by `state`/`reason`; it renders no free
text from Vektra except names, dates and the notice URL (escaped by Mustache). Unknown keys ->
`unavailable`.

**Iframe embed (ARCH-076)**:
- `<iframe src="{ui_origin}/api/v1/assess/ui?cmid=..." sandbox="allow-scripts allow-same-origin allow-forms allow-downloads" referrerpolicy="no-referrer" allow="" title="...">`.
  `allow-same-origin` is required for the iframe's own fetch to its origin; it is safe only because
  `ui_origin` is a different origin from Moodle (A2 refuses a `uiurl` equal to `$CFG->wwwroot`'s
  origin). No `allow-top-navigation`, no `allow-popups`. Final attribute set agreed with plan 9.
- Handshake: iframe posts `{type: "vektra-assess-ready"}`; parent accepts only if
  `event.origin === ui_origin` AND `event.source === iframe.contentWindow`; then calls the `mint`
  action and posts `{type: "vektra-assess-token", token}` with `targetOrigin = ui_origin` (never
  `'*'`). One token per ready message; a second ready triggers a new mint (resume re-mints, INT-001).
- Inbound messages accepted: `vektra-assess-closed` (re-fetch state, re-render button state 6),
  `vektra-assess-resize`. Everything else ignored. The token never appears in a URL, a DOM
  attribute or a log.

**Own transcript download** (`transcript.php?cmid=&tid=&sesskey=`): require_login + sesskey +
`:viewowntranscript` + login-as refusal (REQ-084) -> `POST /transcripts/{tid}/download-token`
(mint key, `sub` = `$USER->id`) -> `assess_client::stream('/api/v1/assess/transcripts/{tid}', token, ...)`.
Bytes are forwarded as they arrive; nothing is written to the File API, `pluginfile.php`,
`make_request_directory()` or the session. Headers set by the plugin itself, before the first
byte, only after Vektra answered 200: `Content-Type: text/html; charset=utf-8`,
`Content-Disposition: attachment; filename="<name from Vektra, validated against the BR-016 pattern>"`,
`X-Content-Type-Options: nosniff`, `Content-Security-Policy: sandbox; default-src 'none'`,
`Cache-Control: no-store`, `Referrer-Policy: no-referrer`. Non-200 -> no bytes forwarded; Moodle
error page with the generic string, or the purge string ("Trascrizione non più disponibile (periodo
di conservazione scaduto)") when Vektra returns its purged code. The proxy class
`\local_vektradiscuss\local\transcript_proxy` is built here and reused by P3 for graders.
`\core\session\manager::write_close()` before streaming to release the session lock.

## State & Data Lifecycle

| State element | Created by | Updated by | Invalidated/Deleted by |
|---------------|-----------|------------|------------------------|
| Pre-session token (in browser memory of `frame.js` and the iframe only) | B1 `mint` -> C4 postMessage | never (one per ready message) | page unload; Vektra TTL and single-use jti; never stored server-side or in browser storage |
| Discarded state-call tokens | B1 `state` (server memory only) | never | end of PHP request; Vektra TTL (unused jti) |
| Download token | E1 (server memory only) | never | end of PHP request; single-use, TTL <= 2 min in Vektra |
| Rendered button state | C3 (DOM) | re-fetch on load and on `vektra-assess-closed` | page unload; no cache anywhere (F3 guard) |
| Behat stub fixtures and request log (`config_plugins` rows, behat site only) | D1 steps | D1 stub | behat reset between scenarios |

The plugin persists nothing about students or sessions in Moodle.

### Implementation notes (2026-11-06/07)

**Alignment to the vektra-stack code** (plan 8, branch feat/assess-session-lifecycle-m3-m5; agreed with
the vektra-stack session):
- `GET /api/v1/assess/state` takes no `?cmid=`: the cmid travels in the pre-session token, which is
  authoritative. Design Notes step 4 is read that way.
- `plugin_version` is read from the mint body (`MintRequest`), not from a header. The plugin sends it in
  the body and keeps the `X-Vektra-Plugin-Version` header (ignored by Vektra).
- Vektra state `starting` renders as state 5 (resume); the iframe shows the preparation from its SSE.
  `reset_granted` is state 10. States 8 (`loginas`) and 9 (`not_selected`) are local and refused if
  Vektra ever sends them.
- The `/state` DTO is extended by vektra-stack (pre-session, `active`, `selected_attempt` in plan 9;
  `transcripts[]` in plan 10). Agreed schema, every field optional:
  `opens_at`, `session_no_next`, `active{session_no, minutes_left, deadline_at}`,
  `selected_attempt{attempt_no}`, `pre_session{duration_min, recipients[{role, name}],
  course_material_used, limits{max_message_chars, messages_per_min}, privacy{notice_url,
  notice_version}, previous_sessions, files[{name, predicted: readable|partial|unreadable}]}`,
  `transcripts[{tid, n, available, purged}]`. `state_dto` keeps only typed, bounded values and renders
  only what is present; the texts (privacy summary, AI disclosure, REQ-093 statement, course material)
  are this plugin's strings.
- Dates of states 6 and 11 (agreed 2026-11-06): `closed_at` in state 6 and `ended_at` in state 11, ISO-8601,
  optional, added to the plan 9 `/state` contract. Each date is read only in its own state; without it the
  sentence has no date.

**Design decisions taken here**:
- The template context is built server-side (`state_view`) with the user's language strings; the AMD
  module only renders `local_vektradiscuss/button` with it. `ajax.php` returns the context for
  `state`, and `{state: ready, token, expiresin, uiorigin}` for `mint`.
- State 9: on the quiz review page the viewed attempt's number (own attempt, read from
  `quiz_attempts`) is compared with `selected_attempt.attempt_no`; display only (BR-012).
- The UI origin is passed to `entry.init` (not a secret): it is the iframe src and the only origin the
  handshake accepts; the mint response repeats it and `frame.js` refuses a mismatch.
- `frame.js` posts `{type: "vektra-assess-unavailable"}` to the UI origin when the mint fails, so the
